## Architecture and normalization

Existing extension points: environmentalDemo is presentation-only; ForecastInput contains operational volumes/rates and the simulator adapter applies only operational controls. Both remain independent of environmental ingestion. The Data placeholder becomes /dashboard/data; existing routes remain available. No duplicate water model.

model.ts contains typed provenance, value kinds, normalization and freshness policy; provider.ts contains HTTP ingestion, bounded timeout, coalescing, validation handoff and memory caching. /api/environment exposes only this fixed-region provider; workspace.tsx presents results. No arbitrary URL proxy, browser credential or downloaded SDK.

Endpoint: https://api.open-meteo.com/v1/forecast

Parameters: latitude=18.5204, longitude=73.8567, hourly=rain,showers,precipitation, models=icon_global, past_days=2, forecast_days=3, timezone=GMT, timeformat=unixtime.

Validate object structure, UTC offset, explicit units, finite nonnegative values, matching arrays, hourly contiguous timestamps, nearby returned grid and complete 24-hour windows. Missing/null input fails validation; missing does not become zero. Past rainfall sums rain + showers over the 24 preceding hourly intervals ending at the current completed UTC hour. Forecast precipitation sums the next 24 hourly intervals (includes snow water equivalent). Open-Meteo hourly amounts describe the preceding hour; exclude the start endpoint and include the end. ISO UTC normalized timestamps are displayed in IST. Returned grid is distinct from requested coordinates.

fetchedAt is retrieval time; latestAvailableEstimate is the end of the selected past window, not the latest future forecast and not model run time. observationTimestamp and modelRunTimestamp remain null because this endpoint does not provide station observations or run issue time. generationtime_ms is processing duration and is never interpreted as timestamp. All indicators retain source, value kind, units and valid windows. Observed and user-provided kinds are reserved for future sources; no current value uses them.

## Freshness and failures

Freshness is an application policy, not a scientific accuracy score: worst of retrieval age and latest past-window age; fresh ≤6h, aging ≤24h, stale >24h. A recent response does not establish recent model issuance. Normalizer rejects a response unable to cover the requested windows; a previous validated snapshot can still be served, explicitly cached/stale with its original windows.

8-second timeout covers fetch and JSON ingestion; abort plus Promise.race bounds even noncooperating transports. Concurrent requests coalesce. Valid data reused for 15 minutes per process. Failed attempts have 60-second retry cooldown; HTTP 429 has 5-minute cooldown (provider Retry-After is not currently parsed). Invalid JSON/fields, rate limit, timeout, network/HTTP unavailability remain explicit. Last successful data survives failures in memory with unchanged timestamps and freshness recomputed; no successful snapshot means unavailable with no numbers. Cache is lost on restart; multiple server workers have independent caches. No persistent environmental cache or disk download.

Offline demo requires explicit selection. Illustrative 4.2 mm / 7.8 mm are fixed fixture values at 7 October 2026 08:00 UTC, labeled demo with JalDrishti attribution; they never automatically replace API data. Existing Overview seeded environmental and storage indicators retain demo labels plus a fixed reference timestamp and a link to genuine public weather context.

## Scientific boundary

No water-security score, storage, demand, supply, leakage, simulator calculation or critical date changes. No building-level inference, validated drought classification, rainfall anomaly baseline, groundwater recharge inference or soil-moisture inference. A harvesting model needs verified catchment area, capture efficiency, losses and timing before precipitation can become tank input. The disabled simulator rainfall control remains disabled. Operational scenario dates use the frozen seeded reference independently of actual weather request time.

Tests use mocks only. artifacts/phase-4-live-result.json records a genuine one-off provider request on A:, including provenance and windows, for manual demonstration; it is never used as application fallback.

The presentation recomputes freshness every minute while open; it does not automatically fetch new values. Refresh remains explicit. Client requests have a 12-second abort limit.
