## Operational inputs and CSV

Required: name, coordinates, IANA timezone, tank capacity/current storage, timezone-qualified ISO reading timestamp, expected daily supply, entered daily consumption OR sufficient imported site consumption, explicitly entered additional loss (0 allowed), and reserve policy. Occupancy is optional context. No seed values or automatic population-to-demand coefficients. Storage provenance must match the reading timestamp. Forecasts start at that reading, so old readings produce forecasts anchored in the past rather than a false current forecast.

CSV UTF-8 schema: `timestamp,storage_liters,supply_liters,consumption_liters,zone`. Timestamp and at least one liters field required; zone defaults to site (documented whole-site scope). Storage is instantaneous; supply/consumption are preceding daily interval totals. Units are liters, not cumulative meter readings. A cumulative meter must be converted into interval consumption before import. Quoted cells supported. Naive/invalid dates, negatives, nonnumeric values, duplicates and malformed rows are rejected. Accepted rows are sorted; summary reports accepted/rejected/range/zones/missing fields/order. Max 500 rows / 500 KB. Records cannot be later than the operational reading. Browser file/text contents remain session-local; reload clears them. No upload/persistence in this phase.

Demand baseline: median of latest up to 28 consecutive daily **site** consumption totals, minimum 7, ending within 26 hours of the reading. Consecutive intervals must be 22–26 hours apart (allows local daylight-saving shifts). Gaps/sub-daily totals are not extrapolated. Zone totals never automatically summed: prevents site/zone overlap double counting. A robust median resists isolated outliers; it is not ML.

Zone anomaly: latest recent consumption vs median of 7–28 prior consecutive daily readings. MAD = median(abs(history − median)). Flag upper excess > max(3 × 1.4826 × MAD, 20% × median, 1 L). Zero baseline has no percentage deviation. Insufficient/sparse/stale history yields no expected value or flag. This heuristic has no calibrated statistical confidence and does not confirm leakage. It never adds excess to tank outflow: measured site consumption may already contain it. Only an explicit user-entered loss _outside_ entered consumption is added; do not double count.

## Reserve policy and deterministic calculations

Essential demand = daily demand × user essential fraction (0–100%, greater than zero). Critical = essential demand × user reserve hours / 24; alternatively explicit user reserve liters. Warning = max(critical, essential demand × warning hours / 24). Required hours/fraction also define warning policy when volume mode is selected. Warning hours >= critical hours, all reserves <= capacity. No 2,236 L/10,000 L demo thresholds in real input.

Original storage engine: each day storage changes by expected supply − entered/derived demand − explicit additional loss, clamped [0,capacity]. Same original scenario adapter: demand reduction, supplementary volume, initial supply delay and hypothesis to remove entered additional loss. Outputs recomputed from real baseline; 30-day horizon. No crossing within horizon means only a bounded result. Rainfall remains contextual. Optional rainwater harvesting was not implemented: no catchment area, capture efficiency or tank connection was provided.

## Decision-support index jd-wsi-1.0

Central policy in model.ts. Component scores clamped 0–100:

| Component                   | Weight | Score                                                                         |
| --------------------------- | -----: | ----------------------------------------------------------------------------- |
| Operational storage         |     25 | 100 × (storage − critical) / (capacity − critical); zero if denominator zero  |
| Supply balance              |     25 | 100 × supply / (demand + additional loss); 100 if outflow zero                |
| Critical runway             |     30 | 100 × days to critical / 14; no crossing in the 30-day analysis scores 100    |
| Anomaly pressure            |     10 | 100 × proportion of adequately assessed zones without an upper-deviation flag |
| Historical rainfall context |     10 | 100 × ERA5 recent-window total / matching prior-three-year mean               |

Missing components have null scores/contributions; available weights renormalize to 100%. Rainfall enters only with available validated historical comparison and nonzero historical mean. Cached failure data excluded. Missing zone history excludes anomaly component. Soil moisture and groundwater displayed contextually, not scored without defensible regional thresholds/baselines. Classification: <40 HIGH STRESS, <70 WATCH, otherwise LOWER OPERATIONAL STRESS. Score rounded, component contributions unrounded. Data completeness reports components/weight and environmental variable counts; no numerical certainty. This is a JalDrishti decision-support index, **not an official government or scientific standard**. Weights/thresholds are engineering choices, unvalidated against outcomes. Rain context does not change storage.

## Environmental sources and bounded ingestion

| Source                                                                     | Coverage / resolution                                                         | Availability / update                                                        | Use                                                                                                                                        |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| [Open-Meteo ECMWF](https://open-meteo.com/en/docs/ecmwf-api)               | Global IFS 0.25° (~25 km); hourly API interpolation of native 3/6-hour output | ~6-hour model updates; past 7 days + 3 forecast calendar days                | precipitation, rain, modeled runoff, ET0, soil moisture 0–7/7–28/28–100 cm                                                                 |
| [Open-Meteo ERA5](https://open-meteo.com/en/docs/historical-weather-api)   | Global 0.25°; daily aggregation                                               | Daily reanalysis with ~5-day publication delay                               | Seven-day window ending seven days before retrieval, compared with matching windows in prior 3 years; only 28 daily rows across 4 requests |
| [NASA POWER](https://power.larc.nasa.gov/docs/methodology/meteorology/)    | Global MERRA-2 0.5° × 0.625°; hourly/daily meteorology                        | Historical context from 1981; publication lag varies                         | Evaluated; ERA5 chosen to avoid adding another model/API and to compare like-with-like                                                     |
| [CGWB](https://www.cgwb.gov.in/ground-water-level-monitoring) / India-WRIS | Regional wells, seasonal monitoring                                           | Authoritative publications; automated endpoint not established in this phase | Provider interface and source-qualified import, no brittle interactive scraping                                                            |

Open-Meteo data CC BY 4.0; public API noncommercial limits apply; commercial use needs appropriate service terms. NASA/CGWB not ingested automatically, so their publication-specific reuse terms must be reviewed before distributing imported datasets. No large dataset downloads. CGWB monitoring is regional and seasonal; a single imported depth cannot establish trend, aquifer stress or campus level. Import requires CGWB/India-WRIS HTTPS URL, valid time, region, coordinates and depth in m below ground. User transcription is not independently verified.

ECMWF request: `https://api.open-meteo.com/v1/ecmwf`, explicit `models=ecmwf_ifs025`, coordinates selected by user, GMT Unix time. Historical: `https://archive-api.open-meteo.com/v1/archive`, `models=era5`, daily precipitation_sum/temperature_2m_mean. No cross-model rainfall ratio. Three prior years are a **short same-season comparison**, not climatological normal. Recent ERA5 window is delayed, not live rainfall. Separate potential ET unavailable on selected endpoint; ET0 is FAO reference demand, not actual ET or a substitute for every potential-ET definition. Runoff is regional modeled runoff, not drainage measurement or tank inflow.

Every regional indicator reports source/model, requested/grid coordinates, spatial context, units, retrieval/valid time, freshness and aggregation window. API variable units, array length, numeric ranges and ordered hourly timestamps validated; missing fields stay unavailable. Soil water fraction remains m³/m³, not percentage saturation. Forecast precipitation window may be shorter than 72 hours because provider returns 3 calendar days; exact window shown. Model-run issue time is not provided/claimed. Freshness reflects usable valid time and retrieval, not a verified current model cycle.

Each fetch bounded at 8 seconds, abort + Promise.race; HTTP rate limits, invalid data and unavailable/timeout states explicit. Up to 20 location-keyed process cache entries, 15-minute TTL with in-flight deduplication. Failed refresh can return prior location-matched data explicitly cached/stale with original timestamps. No demo substitution. New location cannot receive another location's cache. Browser request bounded at 12 seconds. Cache not durable/shared across Lambda instances. Five bounded requests per cold location load; public service quotas apply.
